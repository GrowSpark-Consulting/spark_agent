# 14 Oct (Dev 1): the manual connect also sends `whatsapp/connected` (PR 5). What was built, and what touches Dev 2's and Dev 3's areas

Dev 1 files only: `backend/src/channels/whatsapp/connect/` (`connected-event.ts` new, `manual.ts`, `embedded-signup.ts`, and their tests) and the contract doc. No shared file, no SQL, nothing of Dev 2's or Dev 3's changed. No consumer is added.

1. **Why**: the handover says every connection path emits `whatsapp/connected`; until now only Embedded Signup and the assisted link did (PR 2 and 3 listed the manual path as a follow-up).
2. **One helper**, `sendConnectedEvent` (`connected-event.ts`), now used by all three paths: `{ name: "whatsapp/connected", id: "whatsapp_connected:<connectionId>:<ran_at>", data: { tenantId, connectionId } }`. Ids only (no phone number, token or secret). The id holds the time of the checks that made the connection, so a later reconnection of the same row is a new event and a repeat of the same one is dropped by Inngest. Best effort, and bounded: the connect waits at most 3 seconds for Inngest (the connection is already saved, so a slow Inngest must not hold the answer or the test message check back; `inngest.send` itself has no timeout), then goes on. A failure to send, or that timeout, is logged with the fixed line `[whatsapp-connect] the connected event could not be sent` and never fails or undoes the connection. The Embedded Signup code was moved onto the helper with no change in behaviour (its tests are unchanged and pass).
3. **Manual connect**: sent only when the connection is saved `active`, right after the save and the audit row and before the test message check (so a failed audit write, or a failing test message, does not stop it, and a failed send does not stop the test message). Not sent when the connection is saved `failed`, when Meta cannot be reached, or when the plan has no room (nothing is saved then). A connection connected again in place sends its own event. `ManualConnectDeps.sendEvent` is optional (the default sends through Inngest), so a caller that gives none sends nothing. Both routes, the owner's `POST /api/whatsapp/manual` and the platform admin's `POST /api/admin/whatsapp/manual`, share `connectManual` and so both send.
4. **Tests**: the helper (shape, same check same id and later check new id, never throws with a fixed log line, no sender); manual connect (sent once with ids only and the id with `ran_at`, no secret in it, not sent when saved failed or when nothing is saved, a failing send leaves the connection active and the test message check still runs and nothing leaks, still sent when the audit fails, sent after the save never before, a connection connected again in place). The existing manual tests are unchanged and green.

For Dev 2: `whatsapp/connected` now arrives for every method. Nothing listens yet; when the template submission job is built it can rely on `{ tenantId, connectionId }`, on one event per connection and checks time, and on it being sent only for an `active` connection. It must be idempotent per connection (two retries of one failed row can send two events with different ids). For Dev 3: nothing.

Not changed: recheck. A recheck that turns a `failed` connection `active` does not send the event (the handover names the connect step); say if you want that too.
